## Document Standards

All documentation in this project follows these standards:

1. **Markdown Format**: All documentation must be in Markdown (`.md`) format
2. **Clear Structure**: Use consistent heading structure and navigation
3. **Code Examples**: Include working code examples where applicable
4. **Version Control**: Document all changes in git with clear commit messages
5. **Regular Updates**: Keep documentation current with code changes

## Contributing to Documentation

When making changes to the system:

1. **Update relevant documentation** alongside code changes
2. **Create new documentation** for new features or significant changes
3. **Follow the established structure** and place documents in appropriate directories
4. **Review and test** documentation before committing
5. **Use clear, concise language** appropriate for the target audience
